## 4. Items Needing Human Domain Review

The following components implement deterministic conventions but must be reviewed by a human trader before paper testing:
- **Time/Timezone:** MT5 broker server-time to UTC conversion.
- **Sizing Mathematics:** The exact semantic meaning of `trade_tick_value` provided by the broker and its impact on lot sizing.
- **Formulas & Assumptions:** Wilder ATR, Swing pivots, BOS/CHoCH cross logic, 3-candle FVG, opposite-candle Order Blocks (OB), Zone tolerance calculation, and Fibonacci anchor selection.
- **Configurations:** All provisional settings across `sessions.yaml`, `instruments.yaml`, `risk.yaml`, `jarvis.yaml`, and `strategies.yaml`.

---

**Summary**
The JARVIS project is currently a NO-GO for paper testing or manual trading. While the database structure, safe MT5 fetching, and most dashboard visual components are properly implemented, critical missing functionality acts as a hard blocker. The LLM AI Guardrails are non-existent, the primary `jarvis` CLI entrypoint is missing, and environmental/dependency issues prevent tests and failure drills from running reliably. The repository pattern is violated by the Coulson agent, and the API has authentication flow vulnerabilities. These issues must be prioritized alongside a formal domain review of the trading formulas before the system can be safely deployed for forward testing.
